# Implementation decisions · 19 October 2026

The supplied documentation is preserved byte-for-byte in `specs/cvd-studio`. Its 56 payload hashes and adjacent ZIP checksum were verified using Python's standard library. The original output directory has not been changed.

- Retain the prescribed Next.js/TypeScript/Tailwind/shadcn-pattern Radix controls, FastAPI/Pydantic/NumPy/SciPy/Pint, Plotly, pytest/Vitest/Playwright stack. No account, database, external service or public deployment.
- Use the exact supplied light/dark tokens and self-hosted IBM Plex Sans/Mono packages, including their bundled OFL licenses. Calm scientific instrument: inputs left, result/evidence right, one teal Run action. Independent gas and substrate temperatures, flux and growth remain distinct.
- Pydantic models are generated from the reviewed JSON Schema with strict types, forbidden extras, and finite numbers. JSON Schema supplements conditional and UUID/date constraints. The API publishes the reviewed OpenAPI document; tests also inspect live routes, strict generated model fields and runtime request/response examples. It does not claim that a verbatim published contract alone demonstrates implementation compliance.
- Exact Python compact sorted JSON (`ensure_ascii=False`, `allow_nan=False`), normalized negative zero, matches the supplied hash envelope. Notes and request identity are excluded from the computational hash. Original request remains in the immutable response.
- Da cannot be serialized as infinity under the strict response contract. Extremely unrepresentable coefficient ratios fail explicitly with NUMERIC_RANGE or NUMERIC_UNDERFLOW instead of returning an infinite Da. No clipping is performed.
- Use spawned OS processes for calculation deadlines, with four active and sixteen queued calculations. A canceled HTTP request holds capacity until its computation ends; deadline kills its process. This favors containment over process startup latency. Queue waiting is separate from the five-second calculation deadline.
- On this restricted Windows host, the native SWC compiler could not canonicalize the workspace path. The exercised fallback is Next's supported Babel compiler and Webpack. The application remains Next.js; development and production use the same compiler path. Tailwind's native CSS build was verified independently.
- Use a nonce-based script CSP, dynamic rendering, local fonts, and the strict Plotly bundle. Inline styles are allowed because Plotly sets layout styles. `unsafe-eval` is development-only. No blanket inline script allowance in production. No HSTS on loopback HTTP; enable it only after domain/TLS review.
- The initial Next-specific ESLint configuration pulled a known high-severity vulnerable glob dependency. Replace that development lint chain with TypeScript ESLint and React Hooks rules. Keep a zero known-vulnerability dependency gate, while recognizing scans are time-specific.
- Baseline state is tab memory, with no automatic localStorage persistence. JSON downloads are the portable record. Imports are schema/shape checked, confirmed before replacing comparison studies, and explicitly untrusted until recomputed. Imported registry records never promote trusted sources.
- Spatial comparison uses the shared precursor-flux observable and shared temperature axis. No optimal-process ranking or invented uncertainty. Each snapshot keeps its own assumptions and provenance.

Scientific data gaps remain intentional: no real A, Ea, hg, beta, density, yield, precursor identities, numeric pressure/flow limits or experimental error thresholds were supplied. No experimental validation has been performed.

Installation adjustment: keep the frontend/backend source layout and one committed npm lockfile, but install all JavaScript dependencies at the root. Windows repeatedly denied npm's workspace link even after access was granted. Root task drivers run the same Next.js/TypeScript/Vitest/ESLint tools in the web directory, without requiring that link. This changes package installation only, not the prescribed application stack or contracts. Next production builds use one build worker to reduce generated-directory contention on the restricted host.

Windows build preparation creates output directories sequentially and leaves `cleanDistDir` disabled on Windows to avoid the host's intermittent recursive-mkdir denial. Linux/container builds keep Next's standard clean output behavior. The route/build manifests are regenerated; release images must use the clean Linux/container path and complete the unperformed container gate.
